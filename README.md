# Project Overview 

For the final capstone project used the ESP32 microcontroller to run a simulated medical monitoring system (theme chosen).

The code uses FreeRTOS to juggle multiple tasks at once, ensuring that critical medical alarms happen instantly.
Core 0 handles all the Wi-Fi and networking to host a live dashboard on a web browser.
Core 1 does all the heavy lifting by running the medical data pipeline and managing hospital resources.

# System Architecture

There is 4 major componenets for the full system architecture.
The system uses data pipelines to pass heart rate information between tasks without dropping it.
A counting system manages four hospital wards sharing a pool of three MRI machines.
A lock protects the pharmacy medication count so two users cannot accidentally update it at the exact same time.
A physical emergency button uses a hardware interrupt to bypass regular tasks and trigger an immediate alarm.

# Task Execution & WCET 

Task          (Priority),      Run Schedule,         Time to Run & What It Does
ECG Sample    (15),          10 ms,                 Takes 224 microseconds to act like a sensor reading patient data and sending it down the line.
Arrhythmia    (10),          20 ms,                Takes 1893 microseconds to read the data and check for an irregular heartbeat.
Alarm Dispatch (5),          40 ms,                Takes 120 microseconds to double-check the data to make sure no emergency alerts got corrupted.
System Log     (2),          100 ms,              Takes 0 microseconds because it is starved out whenever more important tasks need to run.
IV Drip ISR,Hardware Edge,                         Takes about 25 microseconds to jump the line and alert the nurse station instantly when the IV is empty.

The WCET evidence is generated by a custom MEASURE_WCET macro that records the system time immediately before 
and after a block of code runs to calculate its maximum execution time. I wrapped this macro around the 
heaviest workload inside each of our four main rate-monotonic tasks: the ecg_task (simulating ADC sensor reads 
and pushing data to a queue), the arrhythmia_task (pulling from the queue and running floating-point filtering 
math), the alarm_task (calculating a CRC integrity check), and the log_task (running a background sorting loop). Every time these tasks fire, the macro automatically catches their peak runtimes and updates the live system dashboard.

# Hazard Analysis & Fault Injection

Priority Inversion
A critical medical task can get stuck waiting forever if a lower-priority task holds onto a shared lock and gets interrupted by a medium-priority task. 
I fix this by turning on priority inheritance, which temporarily boosts the lower task's priority so it can finish faster and release the lock.

Data Queue Overflow
Patient data can be permanently lost if the system generates heart rate readings much faster than it can process them. 
I prevent this by making the storage queues large enough to hold backups and setting strict task priorities so the processor always keeps up with the incoming data.

Interrupt Delays
A nurse station emergency alarm might take too long to go off if the processor is busy doing background work when the button is pressed. 
I avoid this by keeping the actual button interrupt code incredibly short and immediately passing the heavy lifting off to a dedicated high-priority task.
