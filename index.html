ICU Telemetry & Resource Manager

ESP32 FreeRTOS Integration Capstone

Project Overview

  • This is my final capstone project using an ESP32 microcontroller to run a simulated medical monitoring system.
  • The code uses FreeRTOS to juggle multiple tasks at once, ensuring that critical medical alarms happen instantly.
  • Core 0 handles all the Wi-Fi and networking to host a live dashboard on a web browser.
  • Core 1 does all the heavy lifting by running the medical data pipeline and managing hospital resources.

System Architecture

  • The system uses safe data pipelines to pass heart rate information between tasks without dropping it.
  • A counting system manages four hospital wards sharing a pool of three MRI machines.
  • A lock protects the pharmacy medication count so two users cannot accidentally update it at the exact same time.
  • A physical emergency button uses a hardware interrupt to bypass regular tasks and trigger an immediate alarm.

Hazard Analysis & Fault Injection

Priority Inversion
A critical medical task can get stuck waiting forever if a lower-priority task holds onto a shared lock and gets interrupted by a medium-priority task. We fix this by turning on priority inheritance, which temporarily boosts the lower task's priority so it can finish faster and release the lock.

Data Queue Overflow
Patient data can be permanently lost if the system generates heart rate readings much faster than it can process them. We prevent this by making the storage queues large enough to hold backups and setting strict task priorities so the processor always keeps up with the incoming data.

Interrupt Delays
A nurse station emergency alarm might take too long to go off if the processor is busy doing background work when the button is pressed. We avoid this by keeping the actual button interrupt code incredibly short and immediately passing the heavy lifting off to a dedicated high-priority task.
